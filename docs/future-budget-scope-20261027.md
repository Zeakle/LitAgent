# 完整预算上界审查与已确认的规模方向

2026-10-27，Phase 14.5。每题 100 万 tokens／64 请求保持，无新增模型请求。

## 已验证的阻塞

现有计划限制正文最多 66 个宿主单元、每单元最多 2,000 字符，摘要和结论各最多 3 个单元，但没有正文总字节上限。原生断言抽取的 `claim_text` 只有非空要求；现有诊断长度检查也不限制该字段。

本次用原 `validate_body`、`compile_document`、`chapter_request_input`、`prepare_planned_input`、`request_messages`、`provider_response_format` 和 `review_payload` 重建规模反例：66 个单元、每单元 2,000 个 ASCII 字符、每句仅引用一张合法事实卡。完整来源、定位和局部 schema 均通过原消费者。这是刻意构造的**非科学容量样例**，不经过模型，不作为正文、科学支持或真实费用。

原单请求保守上限为 117,964（131,072 上下文保留至少 10%）。最后一章采用实际完整构造器；Reviewer 列只计算经过原校验的用户输入、包装及 4,096 输出，尚未加入系统提示和原生 schema，因此不能用于正向准入。两列均超过限制，说明**当前局部规模合法不意味着后续请求可容纳**。这不证明现实报告必然需要上述 tokens，也不证明模型会在单次输出限额内产生该样例；不能混淆输出 tokens 与 UTF-8 字节。

另验证：10,000 字符的抽取断言可通过当前 Pydantic 类型和响应长度检查。这不代表原文忠实性或科学支持；它说明不能在预算规划中擅自假定每条未来断言很短。

因此，上一轮字节去重不能直接扣减约 195 万的上下文宽上界。继续缩短 ID 也不能独自证明完整流程能进入 100 万。

## 保持不变的要求

- 完整原文、冻结证据、问题范围与核心覆盖不减少；实际科学断言一条不漏。
- 科学支持率 1.0、引用归属、全局一致性和完整性要求保持；旧报告、评分、费用与 SHA 不改。
- Pro disabled、Lite Reviewer／Evaluation、原输出上限、零重试和独立 Judge／Jev 关闭保持。
- 三份固定材料全部准入前不启动真实套件，不恢复 019，不追加到通过，不自动运行 15 题。

## 已确认方向：预算自适应的整体写作规模

用户已明确选择该方向，架构 `Plan.md` 已追加确认依据并保存原字节备份；生产 v4 尚未实施，现有 v3 默认未改。

新增显式整体规模契约，写作前同时选择并锁定：正文总 UTF-8／序列化规模、段落范围、模型断言容量及修复次数。不能只限制单句长度或依赖章节目标。原 72 单元／128 断言作为历史和全局上限保留；新运行可能选择更小的可完成容量，必须在开始前公开展示。

1. **预算候选**：结合完整冻结来源、固定输出预留、实际构造器和所有必要阶段，逐个验证整体容量候选。候选需要包含总正文和摘要、宿主披露、Reviewer 定位信息、断言文本、实际引用与支持表、各批次和全局检查。互斥分支按原完整路径计算。没有经过证明的字段不能填平均长度。
2. **完整首次核验优先**：在容量候选中仍选择可承担的 0–2 次修复；每次修复包含摘要更新与整篇复评。不得用更小容量把已经生成的断言切掉。
3. **模型与宿主一致**：提示词、原生 schema、本地编译和抽取输出验证使用同一份预锁定边界。模型越界则保存完整原响应并终止为规模超限；不截断、不默删句子、不把未核验项记成通过。
4. **核心质量不让步**：容量内仍必须回答原问题，保留方法、数值和条件。若无法兼顾，保留草稿与缺口，禁止自动交付。预算准入不保证科学通过，也不保证所有题目能容纳。
5. **来源不裁剪**：所有实际引用均使用完整原文。允许无损去重或已有宿主别名；不缩短来源文本，不把引用名单改成较窄章节白名单，不把 benchmark 标注注入模型。
6. **身份与兼容**：新规模契约和选定容量进入 fingerprint 及账本；旧 v2／v3 默认、旧恢复和历史读取保持。无法证明任何完整候选时仍在写作前拒绝。
7. **先离线后真实**：先冻结具体数值及证明，完成最大合法输入／边界越界／两次修复／核心覆盖反作弊测试，再核对三域准入。实际运行次数和预算沿用已有授权，不新增人工审批流程。

这会改变新运行允许生成的报告容量，可能使报告更精练；不能作为原有较大规模一定可以完成的修复来宣称。用户已确认允许新增整体容量契约；具体容量及其 producer／consumer 强制检查仍须完成实现与证明，不能把设计确认写成已准入。

另一选择是维持当前全部容量约束与计量方法：保留安全拒绝，不启动三域真实验收。100 万上限不变，但不能承诺现有输入必然准入。
