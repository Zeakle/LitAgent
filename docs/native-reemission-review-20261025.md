## 核心约束

1. 宿主只识别原raw中已经完整闭合、无重复键且通过既有单元字段契约的文本与引用记录，并保存精确字符范围。字符串中的JSON示例不能被误认作字段。未知字段、未知来源、缺失正文、未闭合字符串、截断、认证或usage错误仍停止。
2. 每个原始字符串必须归入一个完整单元，或归入明确允许的章节/段落字段与标题。未覆盖字符串、单元重叠、重复字段或无法明确归属的内容阻止恢复；不能删掉内容以制造完整覆盖。
3. 生成中性的内容指纹：标题、章节、段落及句子顺序、完整文本、实际引用序列；不在宿主组装“修好的报告”。JSON对象字段顺序可以不同，科学内容、引用归属和段落顺序必须相同。
4. 由同一模型以原schema单独返回新的完整响应，经原JSON/schema验证后重新计算内容指纹。只有完全一致才继续。原失败raw始终保留，不直接补括号、丢字段或接受原坏输出。
5. 正文与摘要使用同一恢复控制器，每个失败call最多一次新请求，所有修改继续共享两次额度。核验器的判断JSON不使用此恢复，不把坏核验结果改成通过。真正科学改写仍由已有原文绑定诊断授权并完整复评。
6. 初稿保留后续阶段额度和全部8批请求槽位。涉及既有评估后的修订时，额外请求必须保留完整候选复评预算；无法证明足够则不发请求。不裁原文、不降低输出预留、不提高上限。
