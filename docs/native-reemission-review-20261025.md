# 正文与摘要的统一无损恢复审查（尚未实现）

012已证明一次数组类型恢复走通，但仍在后续非法JSON处停止。真实结果为[0/3](../benchmarks/survey/results/frozen-writer-three-domain-20261025-012/README.md)，不能据此宣称科学通过率提高。下面是下一步离线设计边界，不是已实现能力。

## 证据与问题范围

对连续父链中的7个真实JSON失败响应做只读审计。012比较章的2894字符包含19个完整句子及引用对象；完整字符串均位于这些对象中，外部只有章节和段落字段。其余样本涉及正文、章节和首次摘要。审计只证明可识别完整单元这一必要条件，尚未验证所有来源enum、完整schema或安全恢复。

统一恢复应继续使用`grounded-writer-v1`的原章节/段落/句子schema，不增加模型输出字段、Agent、来源、模型或预算。供应商内部根因仍未确定；不同时调整temperature、thinking强度、timeout或schema.name来猜测原因。

## 核心约束

1. 宿主只识别原raw中已经完整闭合、无重复键且通过既有单元字段契约的文本与引用记录，并保存精确字符范围。字符串中的JSON示例不能被误认作字段。未知字段、未知来源、缺失正文、未闭合字符串、截断、认证或usage错误仍停止。
2. 每个原始字符串必须归入一个完整单元，或归入明确允许的章节/段落字段与标题。未覆盖字符串、单元重叠、重复字段或无法明确归属的内容阻止恢复；不能删掉内容以制造完整覆盖。
3. 生成中性的内容指纹：标题、章节、段落及句子顺序、完整文本、实际引用序列；不在宿主组装“修好的报告”。JSON对象字段顺序可以不同，科学内容、引用归属和段落顺序必须相同。
4. 由同一模型以原schema单独返回新的完整响应，经原JSON/schema验证后重新计算内容指纹。只有完全一致才继续。原失败raw始终保留，不直接补括号、丢字段或接受原坏输出。
5. 正文与摘要使用同一恢复控制器，每个失败call最多一次新请求，所有修改继续共享两次额度。核验器的判断JSON不使用此恢复，不把坏核验结果改成通过。真正科学改写仍由已有原文绑定诊断授权并完整复评。
6. 初稿保留后续阶段额度和全部8批请求槽位。涉及既有评估后的修订时，额外请求必须保留完整候选复评预算；无法证明足够则不发请求。不裁原文、不降低输出预留、不提高上限。

## 实施验收范围

现有数组恢复兼容路径和历史归档保持原语义；新恢复规则通过显式服务端版本进入身份，不能跨checkpoint复用。只有一套新的正文/摘要恢复控制器，业务输出格式不变。普通API默认和引用展示偏好保持兼容。

测试须同时覆盖真实私有原包重放、公开结构精简fixture、合法JSON正例、字段顺序变化、完整字符串内的伪字段、重复键、未知引文、数字/条件/方法/引文变化、跨段归属、缺失单元、预算、部分失败、取消、重启不重发及两次上限。实际SDK→Synthesis→Reviewer→唯一出口→Evaluation→自动判定必须真实执行，外部传输可替换，科学反例仍须被拒绝。

全部离线完成后才冻结下一版固定三域，仍每题一次、零重试，不恢复012或追加到通过。三域科学质量目标保持未完成，Phase14.5仍为in_progress。
