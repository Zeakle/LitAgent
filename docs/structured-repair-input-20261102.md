# Phase 14.5：结构化修复输入离线验收

2026-11-02。用户批准 `host-structured-repair-v1`：仍最多两次共享修复 HTTP，完整 Evaluation 解释保留本地，修复模型接收宿主定位、结构化问题和完整原文依据。本轮仅离线实现和验收，未调用付费模型，未创建新的真实套件。Phase 14.5 继续 `in_progress`。

## 实际改动

- 首轮同时绑定当前稿的 Evaluation 与 Reviewer 问题；第二轮额外绑定经过原始响应、schema、来源关系和位置认证的失败候选问题，不能覆盖当前稿问题。
- 完整诊断、解释、提取字段及原始响应保留本地。模型收到科学判断的真实类型、状态、原文、实际支持来源和精确目标。无法定位、未知类型或完整指导超限时明确不可修复，不删问题、不改分母。
- 容量不足前的未核验清单单独保存，不冒充“不支持”的科学判断。精简后的全部保留内容仍须完整复评。
- 发送副本用 `issue.target_ids` 单向关联目标范围，严格核对后才共享重复容量记录。修复卡片仅包含 `source_ref`、`evidence_id`、`semantic_status` 查找字段；全部原始 `source_quote`、论文身份、内容 SHA、引用权限及顺序保持。未核验提取摘要不是第二套科学依据。
- 新选择及其指导身份进入冻结参数、预算计划、请求和恢复校验。旧 None 路径、source-map/transport 身份与历史费用读取保持原语义；普通 API 和工作台默认未推广。
- 补充严格整数与位置授权检查，拒绝 `False == 0` 别名及重算 hash 后把当前章节片段关联到其他章节目标的错配。

修改了 6 个生产文件，直接新增 4 个 `tests/test_structured_repair_*.py` 文件。最终 600 项源清单摘要为 `6cf3dbfdbd1f22f23a71a316cdc60d37b01e5a4a9cdc255d1887ef2c53351260`。原 Plan 精确备份后按本次批准更新；最终历史保护包含 31,230 个文件。

## 完整预算证明

三份原冻结材料的新选择均准入，计划额度分别为 few-shot 444 万、ViT 448 万、NeRF 448 万 tokens，合计 1,340 万；每题最高 450 万／64 请求、两次共享修复不变。额度是预留，不是实际费用。

主证明使用两类最大预留模拟：

1. 初始 128 容量：全部前置与后续请求按声明上限结算，包含首次完整核验、两次修复及两次完整复评，共 41 请求；三域模拟消耗分别为 4,032,855／4,064,120／4,064,760 tokens。
2. 动态容量：8 个前置请求全部按上限结算后，由真实控制器从 184 条／12 批选择可负担的 176 条／11 批。首次仅形成容量精简诊断，没有科学评分；随后两次候选完整核验及最终 global 均有锁定额度，共 38 请求。三域模拟总量为 3,714,891／3,746,156／3,746,796 tokens，含余量需求为 409／413／413 万，均在启动额度内。

另有零用量合成节省路径，仅作账本分支附证，不作为最大前置消耗或真实模型 usage。所有预算模拟均非科学判断、非提供商费用。

## 历史保护、失败与未完成事项

最初的新投影曾使完整请求达到 124,513 > 117,964，实际拒绝及当时源码均保留。修复后未追认该结果。私有验收桥的重复包装、字段名和断言范围失误也保留，不能计作生产模型故障或真实费用。

历史纯数据费用审计退出 0：累计 1,120 请求、9,828,197 已知 tokens、1,283,047 历史未知占用保持；038 的 78,205 未知占用不释放。旧 044 仍为原协议失败、未完整 Evaluation、严格交付 0/3；正文、评分、SHA 和费用不回写。

本轮没有新真实正文、科学支持率或交付结果，没有新的浏览器视觉或报告导出验收。离线测试不能证明模型一定正确修复，也不能保证任意主题通过。超出容量或无法安全定位的问题仍会保留并阻止交付。

下一步是在本次固定源码和新指导契约下，按既定边界准备独立三域真实验证；不恢复 044，不追加样本直到通过，不自动进入 15 题，不推广工作台默认。
