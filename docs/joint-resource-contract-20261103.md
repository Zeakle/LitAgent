## 发现的问题与证据范围

### 初始 128 条并不保证最多 8 批

每批最多 16 条，只能推出批次数下界。完整原文、段落上下文、引用权限和 native schema 都影响实际请求大小。

固定 ViT 公开来源的真实生产者向量包含 65 个正文单元及两个摘要／结论单元。正文 JSON 为 31,953／32,000 bytes，断言文本 JSON 为 19,899／30,000 bytes，67 条断言均经实际位置和清单消费者接收。完整分区为 9 批，数量为 `8,8,8,8,8,8,8,8,3`；最大请求预留 92,223，总预留 793,228。所有原始来源与逐断言权限保留。

证据：`artifacts/acceptance/joint-resource-contract-20261103/producer-domain-003/`。该观察器实际进程 97130 退出 0；002 的首个观察器字段错误及原日志保留，不把它当作产品或科学错误。

这证明“初始 8 批是通用上界”不成立，**没有证明整轮资金或 64 次请求已经违约**。假设三轮请求形状和成本相同，9 批的条件算术为 445 万计划额度、44 次请求，仍低于原 448 万／64 次；未知候选并不保证保持相同形状，因此该算术也不是两次修复交易链证明。

### 相同原文单元与相同段落不能混淆

同一原生正文单元内的科学断言共用该单元的实际引用。一个段落可以包含多个正文单元，各自拥有不同引用；不能把整段材料给每条断言兜底。当前冻结正文 66 单元、摘要结论各 2 单元，可限制科学权限组数，但权限组数量本身不能推出批次数或完整成本上界。

### schema 共享尚不足以关闭资源问题

三个完整 128 条有限向量的实际分区都是 8 批。仅共享完全相同的 native schema 子树，每轮共节省 11,329；构造的 spread16 请求共享后仍可能超过 100,000。另一种 membership atoms 表示反而增加成本，未接入生产。

这些是有限资源向量；科学原子性、事实正确性、全部未来候选和服务端 schema 能力均不能据此认定通过。完整请求分项和负结果保存在 `assessment-design-001/`。
