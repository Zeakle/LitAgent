## 依据与改动

旧原 HTTP 探针确认请求确实带有 `json_schema` 和 `strict=true`。当前 SDK 代码及实际 SDK 传输回归也保留这些字段。006 没有捕获 HTTP 原包，不能据此完全排除 SDK 或服务端因素。火山方舟仍将结构化输出标为 beta，提示可能出现结构错误，并建议避免在提示词中重复 schema 的结构信息。[官方结构化输出说明](https://docs.volcengine.com/docs/ark/structured-output-beta?lang=en)

原请求逐层复述 JSON 布局，摘要又要求“只返回 text 和 body_unit_refs”，修摘要时基础指令还指定 fact_card_refs。本次移除重复布局与这些歧义，保留科学写作职责、完整材料和原生 schema。`grounded-writer-v1`、嵌套层级、所有字段、出处权限及宿主校验不变；没有通过补括号、删字段或放宽 schema 接受旧坏响应。此为合理的工程修正，不是已证明的真实质量增益。

执行身份更新为 v8，提示词契约为 `grounded-writer-native-intent-v2`；提示词进入运行及 checkpoint 身份，旧策略指纹和历史读取不变，新旧 checkpoint 不跨版本恢复。仍使用原 Worker、五章加摘要请求及唯一报告出口，不增加请求次数、Agent、模型或预算。

摘要修复的完整 body_units 改放 user 数据，避免将不可信正文拼进 system。修改仍限授权单元，保留原出处、核心覆盖、declined 终态及两次共享修复。响应失败持久化准确 stage、call 和 response_received；未知传输不能据此伪装为未发送。修复外层保留原失败字段，来源投影保留具体 WriterError，而不是包成通用错误。

导出器 view-v5 在没有最终报告 SHA 时显示“运行诊断”，不把草稿或占位归档标成报告。旧公开包、原状态、失败、评分及账本不覆盖。探针历史链补入 006 的真实消耗，防止未来入口丢掉已花费用；本轮不执行付费探针。
