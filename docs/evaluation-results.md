# Evaluation 指标、检查与交付

LitAgent 的严格核验是项目自定义的“实际引用支持率”，不是原生 RAGAS 分数。历史路径保留 RAGAS 提示与适配器。新实验契约为 `independent-evaluation-v1`，只由服务端冻结配置选择；普通 API 的缺省语义不变。

## 执行和职责

同一报告 SHA 只运行一次共享评估。断言抽取负责列出原句和引用；逐条核验唯一负责原子性、分类、原文忠实性与实际引用支持关系；全局负责遗漏、跨章矛盾、核心问题及章节职责。全局不再输出 non_atomic、classification 或 source_fidelity。未知 ID、非法 JSON、缺批次或遗漏仍不能交付。

`EvaluationRunResult` 保存同一执行的断言、逐条结果、全局检查、usage 与故障。运行错误进入持久化结果，序列化和恢复不能把错误变成通过。各指标从共享事实计算，不以某个分数对象充当另一个指标的执行前置。

## 三个指标

| API 键 | 计算 | 有效前提 |
|---|---|---|
| citation_accuracy | 有效去重引用 ID / 去重引用 ID 与格式错误项 | 正文与证据账本可用；只代表 ID 有效性 |
| faithfulness | supported 科学断言 / 全部科学断言 | 清单有效、所有科学断言完整核验，且科学断言非空 |
| internal_consistency | max(0, 1 − 0.2 × 唯一矛盾对数) | 清单完整有效，矛盾区域合法完成；不依赖支持率是否通过 |

基础阈值继续为 0.8。严格交付额外要求科学支持率 1.0、无矛盾、所有必要检查完成并通过。方法或章节检查失败不会抹掉已完成的科学分数，但仍阻止交付。没有科学断言不能得到科学满分。

新指标含 `status`、`score`、`passed`、`skipped`、`reason_codes`。状态为 passed、failed、unverified、error、not_applicable；只有 passed 对应 passed=true，不可用分数是 null。旧归档中的 skipped=true 一律展示未核验，原记录不改。

## 检查与接口

报告新增只读 evaluation_checks，分别暴露执行完整性、清单有效性、核心覆盖、章节分析、结构、方法、语言、方法/组织陈述和具体局限。faithfulness.details 保留同源兼容投影。质量汇总、自动交付、独立核验输入冻结与候选提交共用严格门禁；不计算混合总分。

合法 JSON 的独立检查区域分别验证。区域协议失败持久记录component_errors，保留有效科学分数，但整体执行显示错误；Benchmark控制器停止后续请求，不能将该情况记作核验完成。章节区域损坏不抹掉已独立核验的科学判断；身份错误或全体 JSON 非法仍拒绝。未完整核验的部分数量只作诊断，不当作整篇有效支持率。

## 运行与兼容

既有冻结验收入口的 prepare 阶段可选择 `--evaluation-result-contract independent-evaluation-v1`，配合原有 engineering-closeout-v1 配置。策略及其实现身份进入 envelope、预算、manifest 和 checkpoint；live 不接受临时改选。旧请求/旧策略保留原身份，不跨策略恢复，不修改 057 的评分、SHA 或费用。

清单最多恢复一次，所有入口共用最多两次修改；恢复仍失败时归档。正文候选必须完整复评，失败候选不提交。Judge/Jev 本轮关闭，不新增模型调用、重试或自动付费。

界面与四种 Benchmark 输出使用同源状态和脱敏摘要。公开摘要只含状态、分数、原因码、范围及报告 SHA，不包含完整响应、论文原文或本机路径。离线样例必须明确标记，不算真实科学成功。
